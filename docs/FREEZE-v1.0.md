## 四、诚实的已知缺口

1. **周目之后没有新的「内容形态」**。层 28~76 只是更肥更疼，周目是乘数不是新玩法。要再往上长，得加新机制（地图词缀 / 赛季 / 职业专属技能池）。
2. **天赋树没有重置**。点了就是点了；想回自动只能重开新档（这是为了不引入三态字段，见 D207）。
3. **五行只开三行抗性（金火水）**，木/土怪的元素伤害永远走不到抗性通道（`resWood`/`resEarth` 没数据）。这是**已知的公平性问题**，未修。
4. **打孔镶嵌 / 技能石通货升级 / 地图词缀** 三条需求（REQ §7 用户自标「不确定」）**没做**。
5. **移动端是次优体验**（能点按钮玩，但按电脑网页设计；用户明确说过只做电脑端）。
6. **没有 i18n、没有手柄、没有色盲模式**。
7. **成就/图鉴不给数值奖励**（只有渊痕），这是刻意的（防破坏 24h 曲线），但会让一部分玩家觉得「收集没回报」。

```
README.md                 ← 玩家向：是什么、怎么玩、键位
docs/DECISIONS.md         ← 161 条决策（为什么这么定、否掉了什么、踩过什么坑）

docs/DEPLOY.md            ← 部署
docs/REQ-ZHUOXIAN.md      ← 需求（要什么/不要什么/怎么算做完）
docs/BASELINE-v24h-1.md   ← 24h 内容量基线
```

**改动前后的固定动作**

```bash
node tools/gate.mjs                                  # 五道门，必过
powershell -File tools/_plate.ps1                    # 35 探针 537 项（需先起 server）
node tools/_serve.mjs 5292                           # 起 server（watch: null，改完要重启！）
node tools/probe-live.mjs                            # 线上验收（需 LIVE_PROXY）
```

**三条最容易犯的错（都真实踩过）**

1. **改完 `src/` 不重启 server** —— `_serve.mjs` 是 `watch: null`，探针会测旧代码，「部分通过」先怀疑 server 旧。
2. **探针写死产品文案/按钮顺序/表长** —— 用钩子取几何与数量，断言「方向和结构」而不是「具体数字」。
3. **一份数据两份实现** —— 现在有第五道门（死接线审计）兜底，但几何/命中的重复公式仍要靠 `tests/single-source-geometry.test.ts` 那类守卫。

## 七、这一版最值钱的三条经验

1. **「每个功能都有测试」不等于「玩家能玩到」**。浊气觉醒的 `chooseAscendancy` 从第一天就在、
   单测一直在测，但 `src/` 下单次调用都没有 —— 六行效果四个月没生效。所以第五道门是「死接线审计」。
2. **测试可能在测「没人用的那份」**。同一个几何公式画一遍、算一遍、测第三遍，改一处另两处不变，
   测试永远是绿的。所以 `tests/single-source-geometry.test.ts` 让绘制函数返回几何，再由测试比对。
3. **注释写了用途 ≠ 字段被写过**。`floorMinutes` 有类型、有初始化、有读取方，唯独没有一处 `+=`，
   所有依赖它的诊断读到的永远是 0。这类缺陷不报错、不崩、不红。
