# B 站动态 · 正文排版方案（四款预览）

> 先说一个前提，它决定了你实际能做什么。
>
> **B 站动态的正文编辑器几乎不支持自定义颜色和字号。** 你能用的排版手段就这几样：
> 换行、空格缩进、符号、emoji、部分版本的**加粗**按钮、`#话题#`、@、图片/投票/链接。
>
> 所以「让正文看起来潮」**不能靠选颜色和调字号**，只能靠**结构**：
> 断句的节奏、符号的节奏、缩进的层级、留白。
>
> 下面四套都是**纯文本**，可以直接复制粘贴。字号字色那些留给配图去承担（配图你已说不用改）。

---

## 通用前提：四条排版杠杆

| 杠杆 | 怎么用 | 效果 |
|---|---|---|
| **断行** | 一行只放一件事，别把三件事挤在一行 | 信息流里长行会被跳过，短行会被读完 |
| **缩进** | 用全角空格 `　` 或 `  ` 做出层级 | 比符号更干净，符号太吵 |
| **符号** | `▸` `·` `→` `✓` `—` | 给视线一个落点，扫读友好 |
| **留白** | 段落之间空一行 | 空行比任何装饰都管用 |

**符号选择建议：**

| 符号 | 气质 | 用在哪 |
|---|---|---|
| `▸` | 干净、克制、技术感 | 功能清单（**最推荐**） |
| `·` | 中性、朴素 | 功能清单的保守版 |
| `→` | 有方向感、动态 | 描述"从 A 到 B"的变化 |
| `✓` | 完成态 | 勾选清单、验收通过 |
| `—` `｜` | 分隔 | 标签行、日期行 |
| `▍` `█` | 块状、硬核 | 数字强调（慎用，容易土） |

**emoji 要不要用**：B 站动态里 emoji 显得很"网感"但也容易廉价。
**建议：每条最多 1 个，放在行首当视觉锚点，不要每行都放。**

## 方案 A · 极简清单（**我最推荐**）

```
第 1 天，从零写了个能跑的小游戏

4 小时，4 个功能：

▸ 方块匀速移动
▸ 键盘控制（WASD / 方向键）
　 松手即停，撞墙卡住
▸ 三个敌人自动寻路追击
▸ 碰撞体积，贴住即停不穿模

296 行代码　13 项自动验收全部通过

下一期：自动战斗

既是从零开始做游戏，也是从零开始学 AI

#独立游戏 #游戏开发 #TypeScript #从零开始做游戏
```

**要点**
- 标题行单独一行，不加任何符号 → 一眼看到"第几天"
- 功能用 `▸`，二级说明用全角空格缩进 → 有层级但不吵
- 数字行用全角空格分隔，不用 `·` 也不用 `|` → 干净
- 结尾句单独成段，前后各空一行 → 这是系列的"签名"

**为什么推荐**：扫读速度最快，信息流里 2 秒能看完并抓住三个关键词（4 小时 / 296 行 / 13 项）。

## 方案 B · 极简大字（靠留白制造节奏）

```
第 1 天

从零写了个
能跑的小游戏


4 小时
296 行代码
13 项自动验收


下一期
自动战斗

既是从零开始做游戏
也是从零开始学 AI

#独立游戏 #游戏开发
```

**要点**
- 大量空行，每个数字独占一行 → 视觉冲击靠"空"而不是"多"
- 完全不用符号 → 极简、克制
- 缺点：信息密度低，读者可能觉得"就这？"

**适合**：想走"性冷淡"路线，或者你以后的系列要更偏文艺。

## 方案 C · 终端 / 命令行

```
$ day-01

  ✓ 主循环 + 渲染
  ✓ 键盘输入 (WASD / 方向键)
  ✓ 敌人自动寻路
  ✓ 碰撞体积 (贴住即停)

  4 features
  296 LOC
  13/13 passed

> next: 自动战斗

既是从零开始做游戏，也是从零开始学 AI

#独立游戏 #游戏开发 #TypeScript
```

**要点**
- `$` 起手 → 一眼看出是"跑命令"的语境
- `✓` 是完成态，程序员最熟的符号
- `LOC` / `passed` 用英文 → 有技术味，且不比中文长
- `> next:` 模拟命令行提示符 → 有"下一条指令"的期待感

**优点**：和你的项目气质统一（本来就是终端里敲 `npm run dev` 跑起来的）。**受众窄但精准，程序员和做技术的人会喜欢。**

## 方案 D · 时间线（适合长内容）

```
第 1 天 · 从零写了个能跑的小游戏

14:06  主循环与渲染
       固定步长，逻辑永远按 1/60 秒推进

18:47  键盘输入
       分三层：输入 / 逻辑 / 渲染

19:29  敌人寻路
       单位向量，把距离差压成方向

20:37  碰撞体积
       贴住时中心距 (40+32)/2 = 36

296 行代码　13 项自动验收全部通过

下一期：自动战斗

既是从零开始做游戏，也是从零开始学 AI

#独立游戏 #游戏开发 #TypeScript
```

**要点**
- 时间戳是天然的"进度感" → 让人知道你真的花了一整天
- 时间后用两个空格分隔内容，冒号对齐 → 不需要表格也能读
- 第二行缩进放结论 → 一行时间一行结论，信息不挤

**优点**：长内容时最好读，也最能体现"真实记录"。**缺点**：短内容用这个会显得空。**

## 怎么挑

| 想要 | 选 |
|---|---|
| 通用、扫读最快、长期可复用 | **A** |
| 走性冷淡/文艺路线 | B |
| 程序员看了会笑，气质最统一 | **C** |
| 内容长、要体现"花了一天" | D |

**A 和 C 其实是同一套骨架**（清单 + 符号），只是符号不同：想低调用 `·`，想有技术味用 `▸` 或 `✓`。
**建议第一期用 A**，等系列做长了、你想强化个人风格了，再往 C 那种更"有梗"的方向走。

## 三个 B 站正文特有的坑

**1. 标签要带 `#` 号且在行尾单独一段。**
`#独立游戏 #游戏开发` 这样写会被识别成话题。写在句子中间容易只识别到第一个。

**2. 全角空格 `　` 比普通空格更稳。**
B 站正文有时会吃掉行首的半角空格。缩进用全角空格 `　`（中文输入法下 shift+空格）几乎不会出问题。

**3. 不要在正文里写"如图"。**
动态的图是独立附件，读者自己会看到。写"如图所示"反而像在念稿。

**另外**：如果你的 B 站版本编辑器确实有**加粗按钮**，可以把方案 A 的「第 1 天」和「296 行代码」加粗。但**别依赖它**——加粗一多就变成 Word 文档了，而真正的"潮流"来自结构，不来自加粗。
